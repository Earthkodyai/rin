# Task 3.7: one simulated run of the whole app (Phase 3 exit)

**Device:** Xiaomi 14T, Android 15 / HyperOS 2.0 · **Build:** debug at the commit that adds this file, VRoid sample model
**Why:** D19 replaced the 14 real mornings with one simulated run: does every path of the app work end to end, and does the log say what really happened? It is not a measurement of waking up; the games' own numbers are in 3.3, 3.4 and 3.5.

## Checklist (frozen before the first ring)
Rings are scheduled from the PC with `DebugAlarmReceiver --es cmd add --ei sec 45 --es mission <m>`, except S10. Before each ring the tester locks the phone and puts it down. Time of day and light do not matter (D19).

| # | Scenario | The tester does | Expected on screen | Expected in the log |
|---|---|---|---|---|
| S1 | Colour pads | Plays and passes | Ring page over the lock screen, Rin's hand demos, pads, she claps, page closes | `MISSION_STARTED type=pads`, `MISSION_PASSED`, `DISMISSED source=mission` |
| S2 | Cup shuffle | Plays and passes | Her table in 3D, 3 right in a row | `MISSION_PASSED type=cups … board=3d`, `DISMISSED source=mission` |
| S3 | Repeat after Rin | Speaks the 3 sentences | Subtitles, mic indicator only while listening | `MISSION_PASSED type=speech`, `DISMISSED source=mission` |
| S4 | "Can't talk right now" | Taps it in Repeat after Rin, passes the game it switches to | Another game takes over the same ring | `MISSION_SWITCHED from=speech`, then `MISSION_PASSED` of the new type |
| S5 | Rin picks | Plays and passes | Today's game, which I predict in chat before the ring from `MissionPlanner.rotate` | `MISSION_STARTED` of the predicted type |
| S6 | Snooze | Taps Snooze once, waits, passes the second ring | Rings again about 5 minutes later with one snooze fewer | `SNOOZED n=1/3`, a second `FIRED … snoozeCount=1`, `MISSION_PASSED` |
| S7 | Emergency hold | First a short press (under 3 s), then a full 3 s hold | The short press does nothing; the hold stops it | Exactly one `EMERGENCY_STOP`, then `DISMISSED source=emergency`, `MISSION_UNFINISHED` |
| S8 | No game (None) | Taps Dismiss | A plain Dismiss button, no game | `MISSION_UNAVAILABLE chosen_none`, `DISMISSED source=screen` |
| S9 | Her page crashes | During the cups I send `DebugCharacterReceiver --es cmd crash`; the tester passes | The still image replaces her, the 2D cups take over, the game goes on | `MISSION_PASSED type=cups … board=2d:page_unavailable` |
| S10 | Diagnostics test alarm | Taps "Test alarm" in Diagnostics, locks the phone, taps Dismiss | Rings about a minute later, no game, hidden from the list | `FIRED … test=true`, `DISMISSED`; the test row is deleted |

**Pass (phase exit, D19):** every scenario shows what the table says, on screen (the tester's word) and in the log (the `ring_events` table pulled after the run), and the log holds **no `EMERGENCY_STOP` other than S7's**.

**Slips:** a slip the tester reports (the wrong button, a ring started unlocked, …) is written here, and that scenario is run again. **A failure** is written here with what happened; before any fix, the options go to the tester.

**Not measured (recorded limits, D19):** real mornings, darkness, wake-up time. The 4 remaining held-out cup rings (6/6 so far, bar 9/10) and the dark rings for the cups and Repeat after Rin were never run.
