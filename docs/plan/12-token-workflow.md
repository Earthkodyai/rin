# 12. การทำงานกับ Claude Code แบบประหยัดโทเคน

1. **หนึ่ง session เท่ากับหนึ่งงาน** (หนึ่ง spike หรือหนึ่งฟีเจอร์) จบงานแล้วอัปเดต `docs/STATUS.md` (ไม่เกิน 30 บรรทัด) แล้วสั่ง `/clear` ถ้า context ใกล้ ~200k ให้สรุปแล้วเริ่ม session ใหม่ (จาก audit ของคุณ คำขอที่มี context 500k ขึ้นไปกินโทเคนถึง 58% ของทั้งหมด)
2. **อ่านเฉพาะที่จำเป็น:** session ใหม่อ่าน `STATUS.md` แล้วเปิดเฉพาะ `phase-N.md` ของเฟสนั้น กับไฟล์ที่ระบุใน "อ่านประกอบ" เมื่อจำเป็น ไม่เปิดทุกไฟล์ใน `docs/plan/`
3. **`CLAUDE.md` เขียนเป็นภาษาอังกฤษและสั้น** (ไม่เกิน 3,000 ตัวอักษร) เพราะถูกโหลดในทุกคำขอ และภาษาไทยใช้โทเคนมากกว่าราว 2 เท่า
4. ใช้ **Android CLI** ในงาน setup (Google ระบุว่าลดโทเคนได้ราว 70%)
5. **Build และ log แบบเงียบ:** ใช้ `./gradlew <task> -q` กรอง logcat ด้วย tag และไม่วาง log ทั้งก้อน
6. **ใช้ภาพหน้าจอเท่าที่จำเป็น** (รูปที่อ่านแล้วจะค้างอยู่ใน context ตลอด) ถ้าตรวจเป็นข้อความได้ ให้ใช้ UI dump หรือเทสต์แทน
7. ไม่เปลี่ยนรุ่นโมเดลหรือ effort กลาง session (cache จะหาย และต้องจ่ายใหม่ทั้งก้อน)
8. ปิด Unity plugin ในโปรเจกต์นี้ (ประหยัดราว 4–5k โทเคนต่อ session) ยกเว้นเมื่อเปลี่ยนไปใช้ Plan B
9. ไม่เพิ่ม MCP server ถ้าไม่จำเป็นจริง (นิยามเครื่องมือกินโทเคนในทุกคำขอ)
10. ห้าม Claude อ่านไฟล์ binary (`*.vrm`, `*.vrma`, `*.ogg`, `*.png`) และโฟลเดอร์ `build/` โดยตั้งเป็น `permissions.deny` ในเฟส 0
11. **สร้าง skill ประจำโปรเจกต์** ด้วย `skill-creator` เมื่อขั้นตอนใดทำซ้ำตั้งแต่ 3 ครั้งขึ้นไป: `rin-build-verify` (build → install → launch → logcat ที่กรองแล้ว), `rin-voice-pack` (บท → TTS → QA → แพ็ก) และ `rin-release` (checklist ปล่อยเวอร์ชัน)
12. ทุกเฟสมีเกณฑ์ "จบเฟส" ที่ชัดเจน เพื่อกันการวนแก้ไม่รู้จบ
