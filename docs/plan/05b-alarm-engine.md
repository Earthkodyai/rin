# 5.3 Alarm engine (รายละเอียดที่มักพลาด)
- ประกาศ `USE_EXACT_ALARM` (Android 13+) คู่กับ `SCHEDULE_EXACT_ALARM` ที่ใส่ `maxSdkVersion="32"` สำหรับเครื่องรุ่นเก่า
- ต้องได้สิทธิ์แจ้งเตือน `POST_NOTIFICATIONS` (Android 13+) มิฉะนั้นหน้าจอเต็มที่มาทาง notification จะไม่ขึ้น onboarding จึงต้องขอให้ได้ และ Diagnostics ต้องเตือนถ้าไม่มี
- Full-screen intent: ตรวจด้วย `canUseFullScreenIntent()` ถ้าไม่ได้สิทธิ์ให้พาผู้ใช้ไปหน้าตั้งค่า
- Foreground service ตอนดัง: ต้องประกาศ type ใน manifest (คาดว่าเป็น `systemExempted` สำหรับแอปปลุกที่มีสิทธิ์ exact alarm หรือ `mediaPlayback`) — **ตรวจกับเอกสาร Android และฟอร์มของ Play ฉบับล่าสุดใน Spike S1**
- Android 17 จำกัดการเล่นเสียงเบื้องหลัง แต่ยกเว้นแอปที่มีสิทธิ์ exact alarm และเล่นเสียงแบบ `USAGE_ALARM` เสียงรินช่วงปลุกจึงต้องใช้ `USAGE_ALARM`
- ตั้งปลุกใหม่เมื่อเกิด `BOOT_COMPLETED`, `LOCKED_BOOT_COMPLETED` (Direct Boot + device-protected storage), `MY_PACKAGE_REPLACED`, `TIME_SET`, `TIMEZONE_CHANGED` และเมื่อสถานะสิทธิ์ exact alarm เปลี่ยน
- หยุดดังเองหลัง 15 นาทีถ้าไม่มีใครตอบ (กันกรณีลืมมือถือไว้แล้วดังไม่หยุด) และบันทึกลง log
- เก็บ ring log (เวลาที่ตั้ง เทียบกับเวลาที่ดังจริง) เพื่อพิสูจน์ความน่าเชื่อถือ และใช้เป็นตัวเลขในพอร์ต
- **กติกาคำนวณเวลาปลุกครั้งถัดไป** (`alarm/schedule/NextTrigger.kt`, ทดสอบใน `NextTriggerTest`, ตัดสินใน task 1.1): เวลาปลุกเป็นเวลานาฬิกาของ timezone ปัจจุบัน ไม่ใช่ instant ตายตัว · ผลต้องอยู่หลัง "ตอนนี้" แบบเคร่งครัด (ตั้งใหม่ตอนดังแล้วจะไม่ดังซ้ำ) · วันซ้ำตัดสินตามวันในเขตเวลาท้องถิ่น · ช่วง DST ที่เวลาหายไป (เช่น 02:30 ตอนนาฬิกากระโดด 02:00→03:00) ให้ดังตอนช่วงนั้นจบ (03:00) ไม่ข้ามวัน · ช่วงเวลาซ้ำ (overlap) ดังครั้งแรกครั้งเดียว ข้อแลกเปลี่ยนคือถ้าตั้งปลุกระหว่างชั่วโมงที่ซ้ำ สำหรับเวลาที่ผ่านไปแล้วรอบแรก จะไปดังวันถัดไป (ประเทศไทยไม่มี DST)
- **ที่เก็บข้อมูล**: Room (`rinalarm.db`) และ DataStore (`settings`) อยู่ใน device-protected storage ทั้งคู่ ผ่าน `data/StorageFiles.kt` เพื่อให้ receiver อ่านได้ก่อนปลดล็อกหลังรีบูต ห้ามใช้ `preferencesDataStoreFile()` เพราะมันวิ่งผ่าน `applicationContext` แล้วกลับไปที่ credential storage · สำรองข้อมูล/ย้ายเครื่องปิดหมด (`allowBackup=false` + `data_extraction_rules.xml`)
- **กลไกการปลุก** (`alarm/engine/`, ตัดสินใน task 1.2, ทดสอบใน `RingPlannerTest` + `AlarmEngineTest`): ตาราง `pending_rings` (ช่องละ 1 แถว: ปลุกปกติ + snooze ต่อ alarm) คือความจริงเดียว ไม่ใช่ AlarmManager · `AlarmEngine` เป็นทางเขียนทางเดียว มี mutex กันทำงานซ้อน · reconcile ทุกครั้งที่บูต/อัปเดต/เปลี่ยนเวลา/เปลี่ยน timezone/สิทธิ์ exact เปลี่ยน/เปิดแอป · ปลุกปกติที่ยังไม่ถึงเวลาคำนวณใหม่ตามนาฬิกา (timezone ใหม่), snooze เก็บเวลาเดิม · เลยเวลาไม่เกิน 15 นาที → ตั้งที่เวลาเดิมให้ดังทันทีแบบ "late" · เลยเกิน 15 นาที → MISSED + แจ้งเตือน "missed alarm" แล้วไปรอบถัดไป · ตอนดังจะตั้งรอบถัดไป (หรือปิด one-shot) **ก่อน** เริ่มเสียง · ไม่มีแถว pending แต่ alarm ยังอยู่ → ยังดัง (ดังผิดเวลาดีกว่าไม่ดัง) ยกเว้นเป็นการส่งซ้ำภายใน 15 นาที · ดังเร็วกว่าเวลาที่เก็บเกิน 1 นาที → ถือเป็น registration เก่า ตั้งใหม่ ไม่ดัง · มีปลุกอื่นดังซ้อน → บันทึก OVERLAP ให้รอบที่ดังอยู่ครอบคลุม
- **ค่าเริ่มต้นที่ผู้ใช้เลือก (1.2):** snooze 5 นาที สูงสุด 3 ครั้ง (ครบแล้วปุ่ม Snooze หายไป) · ค่อยๆ ดัง 30 วินาที จาก -16 dB (≈15%) แบบเส้นตรงใน dB · ถ้าเสียงปลุกของระบบต่ำกว่า 40% จะยกขึ้นเป็น 40% ระหว่างดังแล้วคืนค่า (ถ้าผู้ใช้ไม่ได้ปรับเอง) · audio focus: สายเรียกเข้าพักเสียงแต่ยังสั่น แอปอื่นแย่ง focus ถาวรไม่ทำให้เงียบ
- **ถ้าปิดการแจ้งเตือน:** notification ของการปลุกถูกซ่อนและหน้าจอเต็มถูกบล็อก เสียงยังดัง ทางหยุดคือเปิดแอปจาก launcher ซึ่งจะเด้งหน้าปลุกให้ (ทดสอบบนเครื่องแล้ว 2026-09-27) onboarding ใน 1.4 จึงต้องขอสิทธิ์นี้ให้ได้
- **หน้าตั้งปลุก (1.3, ผู้ใช้เลือก):** ตัวเลือกแบบแตะอย่างเดียว ค่อยๆ ดัง ปิด/15/30/60 วิ · snooze 1/5/10/15 นาที · snooze ได้ 0/1/2/3/5 ครั้ง (0 = ไม่มีปุ่ม Snooze, ช่องความยาวเป็นสีเทา) · ค่าที่อยู่นอกรายการ (เช่นจาก debug hook) แสดงเพิ่มให้ ไม่ถูกเปลี่ยนเงียบๆ · ลบต้องยืนยันใน dialog · กดย้อนกลับตอนมีการแก้ที่ยังไม่บันทึกจะถาม "Discard changes?" · วันเริ่มสัปดาห์ตาม locale · กด Save แล้วปลุกจะถูกเปิดเสมอ และขึ้น toast "Alarm set for … from now" · ชื่อยาวสุด 40 ตัวอักษร · UI เขียนผ่าน `AlarmWriter` (= `AlarmEngine`) เท่านั้น `AlarmRepository` อ่านอย่างเดียว · สวิตช์ในรายการเรียก `setEnabled` ที่อ่านแถวล่าสุดใต้ mutex
