# 5.4 Mission engine และ Bed-return detector
- **ภารกิจหลัก: สแกน QR** (ML Kit Barcode Scanning ในเครื่อง ออฟไลน์) ผู้ใช้พิมพ์/แปะสติกเกอร์ไว้ไกลเตียง ตอน setup ต้องยืนยันว่าสแกนจากบนเตียงไม่เจอ ความแม่นยังไม่ได้วัด → วัดในเฟส 3 ตามเกณฑ์ผ่านตั้งแต่ครั้งแรก ≥ 90% (ที่มา: [S5](../spikes/S5-mlkit.md))
- **ภารกิจถ่ายรูป (ทางเลือก):** CameraX แบบ **พรีวิวสดเท่านั้น** (เลือกรูปจากแกลเลอรีไม่ได้) ภาพประมวลผลในหน่วยความจำ ไม่บันทึกและไม่ส่งออก ผู้ใช้สอนของของตัวเองตอน setup (MediaPipe Image Embedder เก็บแค่ embedding ในเครื่อง) ต้องเปิดไฟก่อน (luma ≥ 70) สแกนแบบนำทางหลายมุม (หน้า/ซ้าย/ขวา/ไกล) + สแกนจากเตียงหลายจุด threshold = ค่าสูงสุดจากเตียง + margin และต้องผ่าน **self-test** (เล็ง 3 ครั้งเจอครบ และเล็งจากเตียงไม่เจอ) จึงจะใช้เป็นภารกิจได้ ระหว่างภารกิจมี feedback สดและมีภารกิจสำรองเสมอ ไม่ต้องมีกระจก
- ไม่ใช้ label ทั่วไปของ ML Kit เป็นภารกิจ (S5: มืดตอนตื่นแล้วจำไม่ได้ ติดจากบนเตียง และไม่มีของในบ้านหลายอย่าง)
- กันโกงแบบพอดีๆ: ต้องมีการเคลื่อนที่ (ตรวจด้วย accelerometer) ระหว่างเริ่มภารกิจกับตอนถ่าย และเป้าหมายเปลี่ยนทุกวัน เป้าหมายคือสร้างแรงเสียดทาน ไม่ใช่ระบบกันโกงที่สมบูรณ์
- ภารกิจเดินใช้ `TYPE_STEP_COUNTER` (ต้องขอสิทธิ์ `ACTIVITY_RECOGNITION`) ถ้าเครื่องไม่มีเซนเซอร์นี้ให้ใช้ภารกิจอื่นแทน
- **Bed-return detector:** รวมสัญญาณจาก step counter, Activity Recognition Transition API (เปลี่ยนจาก WALKING เป็น STILL), เครื่องวางราบและนิ่ง, จอดับ และแสงน้อย ถ้าเข้าเค้า รินจะถามก่อน ("Hey… you're not back in bed, are you?") ถ้าผู้ใช้ตอบภายใน 60 วินาทีจะไม่ถูกหัก Bond
- Sleep API ของ Google (ส่ง SleepClassifyEvent ทุกประมาณ 10 นาที) ใช้เป็นสัญญาณเสริมได้ แต่หน้า codelab ของ API นี้ถูกระบุว่า deprecated แล้ว **ห้ามพึ่งพา** และต้องตรวจสถานะก่อนใช้
