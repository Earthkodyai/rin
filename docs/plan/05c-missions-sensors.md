# 5.4 Mission engine และ Bed-return detector

> **D16/D17 (2026-09-28):** ภารกิจหลักเป็นเกมกับริน 3 เกม (สลับแก้ว, colour pads, พูดตามภาษาอังกฤษ) + wake-up check 5 นาทีหลังปิดปลุก (รายละเอียดใน [phase-3.md](phase-3.md), เหตุผลใน [ADR 0001](../adr/0001-games-replace-out-of-bed-missions.md)) · ตัดภารกิจเดิน (`AccelStepDetector` ใช้เป็นสัญญาณ bed-return) · QR ซ่อนหลัง flag · ถ่ายรูปของตัวเองตัดออก · ข้อความเรื่องเดิน QR และถ่ายรูปด้านล่างเก็บไว้เป็นประวัติ
>
> **D18 (2026-09-30):** ตัด wake-up check และ bed-return detector ทั้งหมด ปลุกจบเมื่อผ่านเกม ([ADR 0002](../adr/0002-no-wake-up-check.md)) · ข้อ "Bed-return detector" ด้านล่างเก็บไว้เป็นประวัติ
- **ภารกิจหลัก: สแกน QR** (ML Kit Barcode Scanning ในเครื่อง ออฟไลน์) ผู้ใช้พิมพ์/แปะสติกเกอร์ไว้ไกลเตียง ตอน setup ต้องยืนยันว่าสแกนจากบนเตียงไม่เจอ ความแม่นยังไม่ได้วัด → วัดในเฟส 3 ตามเกณฑ์ผ่านตั้งแต่ครั้งแรก ≥ 90% (ที่มา: [S5](../spikes/S5-mlkit.md))
- **ภารกิจถ่ายรูป (ทางเลือก):** CameraX แบบ **พรีวิวสดเท่านั้น** (เลือกรูปจากแกลเลอรีไม่ได้) ภาพประมวลผลในหน่วยความจำ ไม่บันทึกและไม่ส่งออก ผู้ใช้สอนของของตัวเองตอน setup (MediaPipe Image Embedder เก็บแค่ embedding ในเครื่อง) ต้องเปิดไฟก่อน (luma ≥ 70) สแกนแบบนำทางหลายมุม (หน้า/ซ้าย/ขวา/ไกล) + สแกนจากเตียงหลายจุด threshold = ค่าสูงสุดจากเตียง + margin และต้องผ่าน **self-test** (เล็ง 3 ครั้งเจอครบ และเล็งจากเตียงไม่เจอ) จึงจะใช้เป็นภารกิจได้ ระหว่างภารกิจมี feedback สดและมีภารกิจสำรองเสมอ ไม่ต้องมีกระจก
- ไม่ใช้ label ทั่วไปของ ML Kit เป็นภารกิจ (S5: มืดตอนตื่นแล้วจำไม่ได้ ติดจากบนเตียง และไม่มีของในบ้านหลายอย่าง)
- กันโกงแบบพอดีๆ: ต้องมีการเคลื่อนที่ (ตรวจด้วย accelerometer) ระหว่างเริ่มภารกิจกับตอนถ่าย และเป้าหมายเปลี่ยนทุกวัน เป้าหมายคือสร้างแรงเสียดทาน ไม่ใช่ระบบกันโกงที่สมบูรณ์
- ภารกิจเดินนับก้าวเองจาก accelerometer + gyroscope (`AccelStepDetector`) ไม่ใช้ `TYPE_STEP_COUNTER`/`STEP_DETECTOR` ของ Android เพราะบน 14T นับการเดินถือเครื่องไว้ข้างหน้าได้ 0 ก้าว แต่นับการเขย่า 31–46 ก้าว ([การวัด 3.1](../spikes/3.1-walk-vs-shake.md)) จึงไม่ต้องขอสิทธิ์ใดๆ ถ้าเครื่องไม่มีเซนเซอร์สองตัวนี้ให้ใช้ภารกิจอื่นแทน · ข้อจำกัด: เขย่าแรงนับไม่ได้แล้ว แต่ขยับเบาๆ เป็นจังหวะเดินยังนับได้
- **โครงที่ทำแล้ว (task 3.1, D15):**
  - **วางแผนตอนเริ่มดัง:** `RingService` วางแผนภารกิจด้วย `MissionPlanner` จาก `MissionChoice` ของปลุก (Rin picks / ระบุภารกิจ / None, schema 4) และความพร้อมของเครื่อง (`MissionReadiness`: สิทธิ์ + เซนเซอร์) ทำก่อนโพสต์ notification จึงตัดปุ่ม Dismiss ออกได้เมื่อมีภารกิจ
  - **Rin picks:** หมุนรายวันตาม epoch day ในภารกิจที่พร้อม ทั้งวันได้ภารกิจเดิม (snooze/ดังซ้ำ) ถ้าภารกิจที่ระบุไม่พร้อม จะสลับไปภารกิจที่พร้อม (`switchedFrom`) ถ้าไม่มีภารกิจไหนพร้อมเลยจะใช้ปุ่ม Dismiss ธรรมดา + log `MISSION_UNAVAILABLE` พร้อมเหตุผล ไม่มีผลกับ Bond
  - **เดิน 30 ก้าว:** `AccelStepDetector` ใช้กฎที่เลือกจาก dev และแช่แข็งก่อน held-out (`tools/steplab/rule.json`) ผล held-out: เดิน 36–38 ก้าวใน 20 วิ, เขย่าแรง 3–6, เขย่าเบาเป็นจังหวะเดิน 32 และตั้งใจแกว่งโกง 28–34 · โค้ด Kotlin ให้ผลตรงกับ `tune.py` ทุกไฟล์ (parity test) · หน้าปลุกล็อกแนวตั้ง (ตอนเขย่าจอหมุนแล้วรินโหลดใหม่)
  - **เสียงระหว่างภารกิจ:** เมื่อหน้าปลุกรายงานความคืบหน้า เสียงเหลือ gain ≤ 0.15 และหยุดสั่น ถ้าไม่คืบหน้า 30 วินาทีจะกลับมาดังเต็มและสั่นต่อ log เป็น `TONE_QUIET` / `TONE_FULL`
  - **หน้าปลุก:** รินเต็มตัว (`frame=full` + ภาพนิ่งแนวตั้งใน `stills/full/`) อารมณ์ตาม `RingPhase`: WAKING โบกมือ, WORKING พยักหน้า, STALLED งอน, PASSED ภูมิใจ + ปรบมือ 2.5 วินาทีแล้วปิด มีป้าย AI ตลอด ปุ่มฉุกเฉินต้องกดค้าง 3 วินาที (log `EMERGENCY_STOP` ให้เฟส 5 หัก Bond) ส่วน Snooze ใช้ได้จนกว่าภารกิจจะผ่าน
  - **Event ให้เฟส 5:** `MISSION_STARTED`, `MISSION_PASSED`, `MISSION_FAILED`, `MISSION_UNAVAILABLE`, `EMERGENCY_STOP`
- **Bed-return detector (ตัดตาม D18):** รวมสัญญาณจาก step counter, Activity Recognition Transition API (เปลี่ยนจาก WALKING เป็น STILL), เครื่องวางราบและนิ่ง, จอดับ และแสงน้อย ถ้าเข้าเค้า รินจะถามก่อน ("Hey… you're not back in bed, are you?") ถ้าผู้ใช้ตอบภายใน 60 วินาทีจะไม่ถูกหัก Bond
- Sleep API ของ Google (ส่ง SleepClassifyEvent ทุกประมาณ 10 นาที) ใช้เป็นสัญญาณเสริมได้ แต่หน้า codelab ของ API นี้ถูกระบุว่า deprecated แล้ว **ห้ามพึ่งพา** และต้องตรวจสถานะก่อนใช้
